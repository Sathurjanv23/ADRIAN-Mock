# Progressive Web App (PWA)

ADRIAN's frontend is installable as a mobile/desktop app via `next-pwa`, which
generates a service worker at build time and wires up the web app manifest.

## What was added

| File | Purpose |
|---|---|
| `frontend/public/manifest.json` | App name, icons, theme color, start URL, shortcuts (SOS, Command dashboard) |
| `frontend/public/icons/*` | Generated app icons (72–512px, incl. maskable + Apple touch icon), matching the shield brand mark used in `TopNav.tsx` |
| `frontend/public/screenshots/*` | Wide (1280×800) and narrow (390×844) screenshots of the home page, referenced in the manifest's `screenshots` field so Chrome/Edge show a richer install dialog instead of a plain popup |
| `frontend/next.config.mjs` | Wraps the Next config with `withPWA(...)`, defining the service worker's caching strategy |
| `frontend/app/offline/page.tsx` | Fallback page shown when a navigation fails with no network and nothing cached |
| `frontend/components/shared/InstallPrompt.tsx` | Captures the browser's `beforeinstallprompt` event and shows a small "Install ADRIAN" banner |
| `frontend/app/layout.tsx` | Adds `manifest`, `appleWebApp`, `icons` metadata and a `theme-color` viewport entry |

Build artifacts the service worker plugin generates (`public/sw.js`,
`public/workbox-*.js`, `public/fallback-*.js`) are **gitignored** — they're
regenerated by `npm run build`, never hand-edited or committed.

## Caching strategy (`next.config.mjs`)

- **`/api/*` (any host)** → `NetworkOnly` — live data is never served stale from cache.
- **Images** (`png/jpg/svg/webp/ico`) → `CacheFirst`, 30-day expiry.
- **JS/CSS** → `StaleWhileRevalidate` — instant load, refreshed in the background.
- **Page navigations** → `NetworkFirst` with a 5s timeout, falling back to `/offline` if nothing is cached.
- Disabled entirely in `next dev` (`disable: process.env.NODE_ENV === "development"`) so you never fight stale-cache bugs while developing.

## How to test it locally

The service worker only builds in production mode — `next dev` intentionally
skips it.

```bash
cd frontend
npm run build
npm run start
```

Then open `http://localhost:3000` in Chrome/Edge:

1. **DevTools → Application → Manifest** — confirms icons, name, colors load correctly.
2. **DevTools → Application → Service Workers** — confirms `sw.js` registered and is "activated and running".
3. Click the **install icon** in the address bar (or the in-app "Install ADRIAN" banner) to add it as an app.
4. Toggle **Network → Offline** in DevTools and reload a page you've already visited — it should still render; visiting a brand-new, never-cached route shows `/offline`.

### On an actual phone

Your phone and laptop need to be on the same network, or you need HTTPS —
PWA install prompts require either `localhost` or a secure origin. Two options:

- **Same Wi-Fi, quick check:** run `npm run start -- -H 0.0.0.0`, find your
  laptop's LAN IP (`ipconfig`), visit `http://<that-ip>:3000` on your phone.
  Chrome on Android will still show the install banner over plain HTTP for a
  LAN address in some cases, but **iOS Safari requires HTTPS** — so this only
  reliably works for Android testing.
- **Real test (recommended):** deploy to your actual host (Vercel, or
  whatever's in `docs/aws-deployment.md`) — HTTPS is automatic there, and both
  Android (banner + "Install app") and iOS (Share → **Add to Home Screen**)
  will work properly.

## iOS notes

iOS doesn't support `beforeinstallprompt` at all — Safari never fires it, so
the in-app `InstallPrompt` banner will simply never appear there. Users must
install manually: **Share button → Add to Home Screen**. The `appleWebApp`
metadata in `layout.tsx` and the `apple-touch-icon.png` are what make that
manual install look right (proper icon, standalone window, no Safari chrome).

## Updating the icons

If the brand mark changes, regenerate icons rather than hand-editing PNGs.
The generator script that produced the current set draws the same shield
path as `TopNav.tsx`'s `NovaLogo` component, so the two stay visually in
sync — recreate it the same way (Pillow, no external SVG renderer needed) if
you touch the logo.

## Production checklist

- [ ] Confirm `NEXT_PUBLIC_API_URL` points at your real HTTPS backend — the
      `NetworkOnly` API rule matches `/api/` on any host, so this doesn't need
      changing.
- [ ] Deploy behind HTTPS (required for service workers/installability outside `localhost`).
- [ ] Re-run `npm run build` after any manifest/icon change and spot-check
      **Application → Manifest** in DevTools before shipping.
